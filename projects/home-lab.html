Case study / Systems

Home Lab & Virtualization Environment

A personal lab built to practice virtualization, Windows Server administration, and networking in an environment where breaking something has no consequences.

status
Ongoing — personal learning environment, not production infrastructure
role
Built and configured entirely by me
tech
Proxmox, Windows Server, Windows clients, Active Directory concepts, virtual networking

Overview

This is a lab, not infrastructure. It exists so I can install, configure, misconfigure, and rebuild the kinds of systems that show up in real IT environments — without any of it mattering if I get it wrong.

Proxmox runs as the hypervisor, hosting Windows Server and Windows client virtual machines on a virtual network. That gives me a small Windows environment I can work through end to end: standing up a server, connecting clients to it, and seeing how the pieces actually fit together rather than reading about them.

Why I built it

My Information Technology coursework covered Windows Server, networking, virtualization, and Active Directory. Coursework tends to hand you an environment that is already working, which teaches you the steps but not what happens when a step fails.

I wanted somewhere I had to build it myself from an empty hypervisor, and somewhere I could deliberately break things to find out how they fail and what the failure looks like from the client side. That is much closer to what support work actually involves.

What I set up

  • Installed and configured Proxmox as the hypervisor
  • Created and provisioned virtual machines from scratch
  • Installed and configured Windows Server
  • Installed Windows client machines to connect to it
  • Configured virtual networking so the machines could talk to each other
  • Worked through Active Directory concepts in a live environment
  • Handled the general system configuration each machine needed

What it lets me practice

  • Virtualization — resource allocation, machine provisioning, and how a hypervisor sits underneath everything else
  • Windows Server administration — installation, configuration, and the roles a server fills for the clients that depend on it
  • Directory services — how Active Directory organizes a Windows environment and what clients rely on it for
  • Networking — addressing, connectivity between machines, and tracing why two systems cannot reach each other
  • Troubleshooting — working a problem from the symptom back to the cause, which is the same skill regardless of environment
  • Rebuilding — tearing an environment down and standing it back up, which is how you find out what you actually understood

Why it's on this site

Support and systems work involves environments you did not build, breaking in ways nobody documented. The value of a lab is that it turns concepts I studied into something I have actually installed, connected, broken, and fixed — so when a Windows client cannot reach a server, I have a mental model of what sits between them.

Where it's going next

  • Adding more client machines to make the environment less trivial
  • Spending more time on the networking side: addressing, routing, and segmentation
  • Documenting the build properly, so it can be rebuilt from notes rather than memory
  • Practicing recovery: snapshots, backups, and restoring a machine after deliberately breaking it
